Case Study

CCM — Construction & Contractor Management

End-to-end real estate project lifecycle platform with multi-role access, inspection workflows, financial management, and a role-aware analytics dashboard.

Node.js PostgreSQL React RBAC Multi-Role Real Estate Financials
Domain Real Estate / Construction
Roles 5 (Super Admin, Admin, Inspector, Contractor, Client)
Live ccm-dev.webelight.co.in

01 / The Challenge

Fragmented workflows across project stakeholders

Construction and real estate project management involves many moving parts — clients, contractors, inspectors, and admin teams — often operating in silos. Manual coordination of inspections, financial approvals, and scheduling leads to delays, lost accountability, and opaque billing cycles.

CCM was built to unify all these actors under a single platform: giving each role exactly the data and actions they need, while maintaining a strict audit trail from project creation through to final invoice.

02 / System Roles

Five distinct roles, one unified platform

🛡️
Super Admin
Platform-level control. Manages admin accounts and global configuration.
👤
Admin
Core operator. Manages clients, projects, quotations, jobs, and invoices.
🔍
Inspector
Site-level actor. Conducts inspections and submits detailed inspection reports.
🔧
Contractor
Executes jobs. Logs time and expense entries against assigned jobs.
🏢
Client
End recipient. Views project progress, inspection reports, and receives invoices.

03 / Core Workflow

From project creation to invoice delivery

01
Client & Project Onboarding
Admin creates a client profile and registers the real estate project, linking it to the client for full traceability.
02
Site Inspection
Inspector visits the site and submits a structured inspection report, which is accessible to the admin and client.
03
Quotation
Admin creates a quotation based on inspection findings, scoping the cost of work before committing resources.
04
Job Assignment
Admin converts an approved quotation into a job and assigns it to a contractor with defined scope and timelines.
05
Time & Expense Logging
Contractor logs hours worked and expenses incurred against the job, building a complete cost record in real time.
06
Invoice Generation & Delivery
Admin generates a final invoice from the job record and dispatches it directly to the client through the platform.

04 / Feature Modules

Key capabilities across the platform

Role-Aware Dashboard
Each role sees contextual analytics — job status, invoice totals, and quote summaries — filterable by weekly, monthly, and yearly ranges.
Inspection Reports
Inspectors submit structured site reports with findings. Reports are linked to projects and inform quotation scoping.
Financial Pipeline
A connected Quotation → Job → Invoice flow ensures no billing step is skipped and amounts are always traceable to source work.
Contractor Time & Expense
Contractors log granular time entries and expenses per job, giving admins full visibility into actual vs. estimated costs.
Schedule & Reminders
Admin sets activity-specific reminders for inspectors, contractors, and clients via the scheduling module — reducing missed deadlines.
Project–Client Linkage
Every project is bound to a single client, ensuring data scoping and preventing cross-client information leakage.

05 / Architecture Insights

Design decisions that drive reliability

CCM is built on a structured RESTful API in Node.js backed by PostgreSQL, with React on the frontend consuming role-scoped API responses. Data visibility is enforced server-side — each API endpoint validates the requesting user's role before returning or mutating data, ensuring that role-based restrictions cannot be bypassed through frontend manipulation.

Server-side RBAC enforcement — Role permissions are validated at the API layer, not relying on frontend routing guards alone.
Linked financial entities — Quotation, Job, and Invoice share foreign key relationships in PostgreSQL, maintaining referential integrity across the billing pipeline.
Role-scoped dashboard queries — Dashboard aggregations (weekly / monthly / yearly) are computed server-side per role, minimising data over-fetching to the client.
Scheduling as a first-class module — Reminders are modelled as independent entities associated with projects, activities, and target roles — supporting flexible multi-stakeholder scheduling.
Inspection-to-quotation traceability — Inspection reports carry a direct reference to the project, enabling admins to scope quotations with full inspection context available in the same UI.
